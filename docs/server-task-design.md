# 服务端任务职责与播客转写示例

本文明确 CLI、Web 应用、共享平台和应用 Worker 的职责边界，并以“播客音频转文本”为例说明新任务应如何接入。核心原则是：**客户端只提供任务基本数据和资源定位信息，领域任务由服务端应用 Worker 实现；共享平台负责任务控制面，不替具体任务获取和处理外部内容。**

## 1. 三层职责

### 客户端层：CLI 与 Web 应用

客户端负责用户交互，不执行领域任务：

- 收集任务类型、选项和少量 JSON 参数。
- 按任务契约提交网页 URL、平台内容 ID、平台资产 ID 等资源定位信息。
- 当任务要求处理用户本地文件时，可以使用平台上传能力；上传不是所有任务的前置条件。
- 提交任务时提供幂等键、单次计划时间等通用控制参数。
- 展示排队、执行、恢复、成功或失败状态，读取进度与日志。
- 下载或展示最终产物。

CLI 与 Web 应用不得包含转码、语音识别、内容分析等核心实现，也不得持有 Worker Token、直接读写平台数据库或自行把本地执行结果伪装成平台任务结果。

浏览器页面原则上通过应用后端调用平台用户 API。若任务输入只是公开网页链接，浏览器与 CLI 只提交链接；页面解析、重定向处理、真实媒体定位和下载都由对应的服务端 Worker 完成。后续引入签名上传 URL 后，本地文件类任务仍可使用平台资产服务。

### 共享平台：任务控制面

共享平台提供所有应用复用的控制能力：

- 用户与 Worker 认证、应用隔离和平台资产授权。
- 任务声明、输入输出 schema 校验和不可变版本绑定。
- 任务创建、幂等、计划时间、队列、租约、超时和恢复。
- 进度、日志、步骤检查点、结果和产物元数据。
- 可选的平台资产上传、校验和、对象存储引用及下载授权。
- 历史、审计和可观测性。

平台 API 不直接调用 FFmpeg、语音识别模型或第三方领域服务，也不为每个业务新增专用 HTTP 路由。播客、图片、报告等任务都通过统一的任务和资源契约接入。

### 执行层：服务端应用 Worker

应用 Worker 是领域任务的实现位置：

- 随应用版本部署任务处理器及其运行依赖。
- 使用应用专属 Worker Token 领取匹配 `app_id` 和 `release_digest` 的任务。
- 根据任务输入解析外部链接、平台内容 ID 或平台资产 ID，取得实际工作资源。
- 执行下载、转码、模型调用、解析或业务计算。
- 管理第三方 API 密钥和模型配置；秘密不得进入任务输入、日志或产物元数据。
- 上报进度和日志，保存可恢复的小型检查点。
- 上传产物并提交经过 output schema 校验的结构化结果。

Worker 可以独立部署和扩缩容。CPU、GPU、内存、网络和第三方服务依赖由对应应用 Worker 决定，不进入共享平台的业务代码。

## 2. 通用任务数据边界

任务输入 JSON 只保存可校验、可审计的小体积数据和资源定位信息：

```json
{
  "source_url": "https://www.xiaoyuzhoufm.com/episode/example",
  "options": {
    "language": "auto",
    "quality": "balanced"
  }
}
```

任务输入应遵守：

- 任务可以显式接受 HTTPS URL、供应商内容 ID 或平台资产 ID；允许哪些定位方式由任务 input schema 和 Worker 版本共同定义。
- 本地文件使用平台资产 ID，不使用本机路径或把 Base64 文件塞进 JSON。
- 外部 URL 由应用 Worker 获取；共享平台只校验任务 schema，不代表平台替所有应用提供通用网页抓取服务。
- Worker 必须处理 SSRF、DNS 重绑定、重定向、大小限制、内容类型、超时和来源变更。
- 客户端体验字段可以放进输入，但不能把模型密钥、Worker 配置或执行脚本作为输入。
- 任务输入在创建后视为不可变；重试和恢复使用相同输入与任务版本。

结构化输出只保存状态摘要和产物引用：

```json
{
  "artifact_id": "artifact_xxx",
  "language": "zh",
  "duration_seconds": 3725,
  "segment_count": 186
}
```

完整文字、图片、音频和报告进入产物存储。若一个任务产生多个文件，目标架构应返回 `artifacts` 数组；当前 MVP 只有一个最终 `artifact_id`，首个播客版本可先只生成一份 Markdown 文字稿。

## 3. 播客音频转文本任务

建议把转写能力注册为独立应用任务：

```text
app_id: podcast-tools
task_key: audio/transcribe
完整任务名: podcast-tools/audio/transcribe
```

客户端只需要提交小宇宙等播客页面链接和基本选项：

```json
{
  "source_url": "https://www.xiaoyuzhoufm.com/episode/example",
  "language": "auto",
  "timestamps": "segment",
  "speaker_diarization": false,
  "output_format": "markdown",
  "quality": "balanced"
}
```

推荐字段：

| 字段 | 说明 |
| --- | --- |
| `source_url` | 播客单集网页的 HTTPS URL，首版必填 |
| `language` | `auto`、`zh` 或 `en` |
| `timestamps` | `none` 或 `segment` |
| `speaker_diarization` | 是否区分说话人 |
| `output_format` | 首版使用 `text` 或 `markdown` |
| `quality` | `fast`、`balanced` 或 `accurate`，避免对客户端暴露具体供应商模型名 |

Worker 的服务端执行流程：

```text
识别来源平台并规范化 URL
  → 解析页面与重定向，取得单集元数据和音频地址
  → 服务端下载音频并计算校验和
  → 探测格式和时长
  → 转换为统一音频格式
  → 按固定时长切片
  → 逐片调用转写引擎并保存检查点
  → 合并文本、校正时间戳和片段边界
  → 生成 Markdown 文字稿
  → 上传产物并提交结构化结果
```

推荐输出：

```json
{
  "artifact_id": "artifact_xxx",
  "language": "zh",
  "duration_seconds": 3725,
  "segment_count": 186,
  "format": "markdown"
}
```

摘要、章节、标题建议和内容审校应拆为后续任务，例如 `transcript/summarize` 或 `transcript/chapters`，输入使用转写产物 ID。这样转写失败恢复、模型选择、成本和版本可以独立管理。

## 4. 恢复、幂等和进度

音频转写是长耗时任务，应按切片保存可恢复检查点，例如 `segment-000001`。检查点只保存片段范围、转写文本、引擎请求 ID 和必要摘要，不保存大体积音频字节。

Worker 恢复时：

1. 读取已确认的来源快照，包括规范化页面 URL、单集 ID、元数据和音频摘要。
2. 读取平台返回的已确认步骤。
3. 跳过已完成片段，从第一个缺失片段继续。
4. 重新生成最终合并产物；只有当前有效尝试可以提交成功结果。

对第三方转写服务的请求应使用稳定的幂等键，例如 `task_id + segment_index + release_digest`。平台提供至少一次执行，应用 Worker 必须避免恢复过程产生重复计费或不可控副作用。

进度建议按阶段映射：

- 0–5%：解析播客页面与定位音频。
- 5–20%：服务端下载、验证、格式转换与切片。
- 20–90%：按已完成切片数量计算转写进度。
- 90–97%：合并、时间戳和格式处理。
- 97–100%：上传产物并提交结果。

## 5. 当前 MVP 与实施顺序

当前本地 MVP 已具备任务声明、Worker 领取、心跳、进度、日志、检查点和文本产物。对于公开播客网页链接，现有 CLI 已经可以通过 JSON 提交 URL，因此播客首版不依赖客户端文件上传能力；需要新增的是服务端 Worker 及其来源解析、下载和转写依赖：

- CLI 的 JSON 输入上限为 60 KiB，足以提交单集 URL 和转写选项。
- Worker 运行环境需要访问目标播客页面、音频地址和选定的转写引擎。
- Worker 产物接口目前固定为文本且最大 5 MiB，首版 Markdown 文字稿需控制在此范围内。
- 当前任务只关联一个最终产物，首版只输出一份文字稿。

建议按以下顺序推进：

1. 固定 `podcast-tools/audio/transcribe` 的输入输出契约和错误语义。
2. 实现可扩展的播客来源适配器，首版支持小宇宙单集链接。
3. 在 Worker 中实现受控下载、媒体探测、切片、转写和合并。
4. 使用检查点保存来源快照和分片结果，支持 Worker 中断恢复。
5. 上传 Markdown 文字稿并提交结构化结果。
6. 验证链接解析、长音频、来源变化、旧尝试隔离和最终文字稿下载。

实现完成后，CLI 和 Web 应用的变化应主要体现在链接输入、选项表单与状态展示；替换页面解析方式、转写引擎、切片策略或模型版本只需要发布新的服务端 Worker 版本，不要求发布新的 CLI。详细、长期维护的功能需求见 [播客转写 Task 需求](./podcast-transcription-task.md)。
