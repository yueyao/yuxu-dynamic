# 采集结果与内容管理需求文档

版本：v0.3
日期：2026-11-08
状态：已实现（2026-11-08）
变更：任务页确定为两个 Tab；采集任务不再与单集库关联；单集库保留采集/转写成功标识

## 1. 背景

当前 Web 端存在三个体验问题：

1. 「节目库」和「候选节目」是两个独立页面，来回切换才能看全节目。
2. 「采集任务」和「转写任务」分散在播客导航里，缺少统一的任务入口。
3. 采集完成后没有全局单集列表，无法按时间浏览，也无法按播客搜索所有单集。

## 2. 目标

1. 节目库和候选节目合并为一个页面，用两个 Tab 区分。
2. 采集任务和转写任务合并为「任务」页的两个 Tab，默认转写任务。
3. 新增「单集库」，默认按时间排序。
4. 单集库展示「采集成功」和「转写成功」标识。
5. 单集库支持按播客名搜索所有单集。
6. 保留现有筛选、分页、加入转写队列能力。

## 3. 非目标

V1 不做：

- 音频在线播放
- 单集编辑/删除
- 采集任务与单集的关联/追溯
- 全库批量转写

## 4. 信息架构调整

### 4.1 导航

建议调整为：

```text
总览
任务
  [转写任务] [采集任务]    ← 默认转写任务
内容库
  [节目库] [候选节目]      ← 默认节目库
单集库
应用
调度
```

说明：

- 「节目库」和「候选节目」不再各自占一个导航项，合并为「内容库」。
- 「任务」是一个页面，内部只有两个 Tab：转写任务、采集任务。
- 进入「任务」默认落在「转写任务」。
- 旧路由 `#/transcribe-queue`、`#/podcast-tasks` 分别重定向到对应 Tab，不保留独立导航项。
- 原通用平台任务列表不再放入这两个 Tab；保留独立路由作为内部排障入口，不占主导航。

### 4.2 节目库合并

路由：

```text
#/podcast-shows
```

页面顶部：

```text
[节目库 17] [候选节目 91] [已忽略 0]
```

- Tab 切换不刷新整页
- 当前 Tab 写入 URL，例如 `#/podcast-shows?tab=candidates`
- 节目库：至少成功采集过一次的节目
- 候选节目：从未成功采集的节目
- 已忽略节目仍在候选 Tab 内通过「显示已忽略」查看
- 两个 Tab 各自保留搜索、全选、批量采集、分页状态

合并后不再保留独立导航项「候选节目」；旧路由 `#/podcast-candidates` 重定向到 `#/podcast-shows?tab=candidates`，避免旧链接失效。

## 5. 任务页面（两个 Tab）

路由：

```text
#/tasks                  → 转写任务
#/tasks?tab=collect      → 采集任务
```

### 5.1 转写任务（默认 Tab）

保留现有「转写」页全部能力：

- 转写队列
- 已入库转写稿
- 队列筛选、分页、多选、批量启停/取消/移除/重试
- 运行中取消任务

### 5.2 采集任务（第二个 Tab）

保留现有「采集任务」页全部能力：

- 采集任务列表
- 状态/类型筛选
- 自动刷新
- 失败重试

### 5.3 默认行为

打开「任务」时默认进入：

```text
转写任务
```

原因：转写是当前最高频操作，采集是上游准备动作。

## 6. 单集库

### 6.1 页面位置

新增导航「单集库」，路由：

```text
#/episodes
```

### 6.2 顶部统计

```text
单集总数        已采集        已转写        未转写
1125           1125          47            1078
```

说明：

- 单集库中所有条目都已经采集成功，因此「已采集」= 总数。
- 仍然显示「采集成功」标识，是为了让用户明确数据状态。
- 「已转写」按 `transcription_transcripts` 是否存在计算。

### 6.3 筛选与搜索

```text
[搜索播客名 / 单集标题 / episode id] [全部播客 ▼] [发布时间范围]
[转写状态 ▼] [来源 ▼] [查询] [重置]
```

关键要求：

- 搜索框必须能按**播客名**搜索该播客下的所有单集
- 同时支持单集标题、episode id
- 选择播客下拉后，只显示该播客的单集
- 支持发布时间范围
- 支持转写状态：全部 / 已转写 / 未转写

### 6.4 排序

默认：

```text
发布时间 DESC
```

可选：

- 发布时间：新→旧 / 旧→新
- 入库时间：新→旧 / 旧→新
- 播客名：A→Z，组内按发布时间新→旧

「按播客排列」V1 先实现为排序，不做分组折叠。

### 6.5 列表

| 列 | 内容 |
| --- | --- |
| 发布时间 | 单集实际发布时间 |
| 播客 | 节目名称 + show id |
| 单集标题 | 过长省略，悬浮显示完整 |
| 时长 | 格式化时长 |
| 采集状态 | `采集成功` 绿色标识 + 采集时间 |
| 转写状态 | `转写成功` 绿色标识 + 转写时间；未转写显示灰色 |
| 操作 | 查看详情、加入转写队列、查看转写稿 |

状态展示建议：

```text
采集成功   2026-11-08 03:12
转写成功   2026-11-08 03:20
```

或紧凑形式：

```text
[✓ 已采集] [✓ 已转写]
```

### 6.6 行操作

- 查看详情
- 加入转写队列
- 已有转写稿时跳过并提示
- 查看转写稿（已转写时）
- 复制音频链接（可选）

### 6.7 分页

- 默认 50 条/页
- 上一页 / 下一页
- 显示总数与当前页

## 7. 接口设计

### 7.1 单集列表

```http
GET /api/podcast/episodes
```

参数：

| 参数 | 说明 |
| --- | --- |
| `q` | 匹配播客名、单集标题、episode id |
| `show_id` | 播客筛选 |
| `since` / `until` | 发布时间范围 |
| `source` | rss / page |
| `transcript` | any / done / pending |
| `sort` | published_at / created_at / show_title |
| `order` | asc / desc |
| `limit` | 20 / 50 / 100 |
| `cursor` | 分页游标 |

响应：

```json
{
  "episodes": [
    {
      "episode_id": "...",
      "show_id": "...",
      "show_title": "张小珺Jùn｜商业访谈录",
      "title": "140. 对姚顺宇的4小时访谈……",
      "published_at": "2026-11-07T00:00:00.000Z",
      "duration_seconds": 14400,
      "source": "rss",
      "collected": true,
      "collected_at": "2026-11-08T03:12:00.000Z",
      "transcript": {
        "transcript_id": "transcript-...",
        "created_at": "2026-11-08T03:20:00.000Z"
      }
    }
  ],
  "total": 1125,
  "next_cursor": "..."
}
```

要点：

- `collected` 当前在单集库中恒为 `true`，用于显式状态展示
- `collected_at` 使用现有 `podcast_episodes.created_at`
- `transcript` 取该 episode 最新一条转写稿
- `q` 必须同时 `LIKE` 播客标题、单集标题、episode id

### 7.2 查询示例

按播客名搜索所有单集：

```http
GET /api/podcast/episodes?q=张小珺&limit=50
```

按播客 + 时间：

```http
GET /api/podcast/episodes?show_id=show-xxx&since=2026-01-01&until=2026-11-08
```

### 7.3 性能

- 服务端分页，禁止一次返回全量
- 需要索引：

```text
podcast_episodes(published_at DESC)
podcast_episodes(show_id, published_at DESC)
podcast_episodes(created_at DESC)
transcription_transcripts(episode_id, created_at DESC)
```

- 当前 1125 条，目标首屏 < 300ms
- 1 万条以内保持可用

## 8. 采集任务与单集库的关系

明确不关联：

- 采集任务行不提供「查看本次结果」
- 不在采集任务与单集之间增加关联字段/表
- 单集库独立按播客、时间、转写状态查询
- 需要核对某次采集时，由用户自行按节目和时间范围筛选

这样 V1/P1 都不引入任务-单集关联模型，减少实现和数据迁移成本。

## 9. 验收标准

### 内容库

- 节目库和候选节目在同一个页面
- 两个 Tab 数量正确
- 切换 Tab 不丢失搜索/选择状态
- 旧候选路由可重定向

### 任务

- 「任务」页内只有两个 Tab：转写任务、采集任务
- 默认打开转写任务
- 旧路由重定向到对应 Tab
- 转写队列和采集任务原功能不丢失
- 通用平台任务列表不占任务页 Tab

### 单集库

- 默认按发布时间倒序
- 能按播客名搜索到该播客所有单集
- 能按播客筛选
- 能按发布时间范围筛选
- 能按转写状态筛选
- 每行显示采集成功标识和转写成功标识
- 已转写显示转写时间
- 加入转写队列时已有转写稿自动跳过
- 分页正确，无重复/丢失
