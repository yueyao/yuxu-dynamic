# 播客应用产品审阅

日期：2026-11-07
范围：登录、总览、节目库、候选节目、单集、转写、采集任务、调度、应用、任务
方法：页面走查、无头浏览器实际点选、接口与数据结构核对

## 结论

核心业务闭环已经成立：

```text
添加/导入节目 → 采集单集 → 选单集 → 转写队列 → Worker 执行
→ 服务端入库 → Web 阅读 / Markdown 下载 / 对外 API
```

基本管理需求可用，但离“长期运营 100+ 节目、上千单集”还有差距。主要问题集中在三处：

1. **节目生命周期不完整**：只有“候选/已采集”两态，没有归档、忽略、暂停更新。
2. **批量操作和筛选不足**：节目、队列、任务的规模上来后，单条操作为主。
3. **状态与自动化反馈不足**：Worker 在线状态、队列 ETA、任务自动刷新此前缺失。

## 逐页审阅

### 登录

符合基本要求：

- 用户名/密码登录
- 30 天会话，服务端持久化，重启 Web 不退出
- 用户名本地记忆
- 错误提示明确

建议：

- 当前是 HTTP，长期应上 TLS
- 可增加“退出所有设备”，单用户场景优先级低

### 总览

原来只统计 Platform 任务，不统计 Web 转写队列，会出现“队列里还有 90 集，但总览显示 0 排队”的错觉。

已优化：

- 执行中/排队数合并平台任务和转写队列
- Hero 增加转写队列状态
- 最近任务优先显示单集标题，而不是 `episode/transcribe`

仍建议：

- 增加“今日完成转写/失败转写”趋势
- 增加 Worker 在线状态和最近心跳

### 节目库

原来已采集和未采集混在一起，108 个节目里 91 个是候选，管理上分不清“持续更新”和“备选”。

已优化：

- 拆成「节目库」和「候选节目」两个页面
- 节目库只显示至少成功采集过一次的节目（`last_sync_at` 有值）
- 候选页只显示从未采集的节目
- 首次采集成功后自动进入节目库
- 两个页面都支持搜索、全选、批量采集

仍建议：

- 增加“归档/忽略”候选节目，避免榜单导入后无法清理
- 增加“超过 N 天未更新”筛选
- 增加删除节目能力
- 对只有公开页、没有 RSS 的节目做明确标识

### 单集

已优化：

- 列表显示发布时间、时长、来源
- 增加「只看今年」
- 全选只选择当前可见单集
- 显示“显示 X / 全部 Y 集，已选 Z 集”
- 单集上限从 200 提高到 500

仍建议：

- 增加「只看未转写」筛选
- 增加按发布时间/时长排序
- 转写队列入库时跳过已有转写稿，避免重复转写
- 超过 500 集时做分页，而不是硬截断

### 转写

原来 90 多条待转写全部铺开，已入库转写稿被挤到页面底部，看起来像“查不到已完成”。

已优化：

- 队列默认只显示前 10 条，可展开全部
- 队列支持搜索
- 待转写项支持「置顶」
- 运行中自动刷新，不必手动点刷新
- 已入库转写稿支持标题/episode id 搜索
- 最近 20/50/100 条切换
- 直接下载 Markdown
- 清空/移除增加确认

仍建议：

- 队列支持多选批量启用/停用/移除
- 增加预计完成时间
- 队列和 Worker 在线状态联动提示
- 历史增加节目、日期筛选和分页

### 采集任务

原来字段是通用任务字段，看不出“采集了哪个节目、什么区间、新增多少”。

已优化：

- 专用字段：时间、类型、节目/范围、采集区间、状态、新增/更新、操作
- 状态和类型筛选
- 运行中自动刷新
- 失败任务可直接重试
- 采集耗时显示

仍建议：

- 增加分页或“加载更多”
- 采集任务失败原因直接在行内展开
- 批量重跑失败任务

### 调度

基本可用：

- 创建、启停、立即运行、历史、删除确认
- 已把 `run-now` 改为「立即运行」

仍建议：

- 支持编辑 cron/时区/输入
- 显示未来 3–5 次触发时间
- 显示调度所属节目和最近运行结果

### 应用

基本可用：

- 注册/更新 manifest
- 查看任务定义
- 轮换 Worker Token（旧 Token 立即失效）

仍建议：

- 显示 Worker 最近使用时间和在线状态
- 允许删除应用
- 并发数可视化编辑

### 任务

通用任务页与采集/转写页存在重叠。

已优化：

- 任务标题优先显示单集标题
- 失败/关闭任务支持重试

仍建议：

- 明确“任务”是排障入口，业务操作去采集/转写页
- 增加分页和自动刷新
- 与采集/转写任务互相跳转

## 建议路线图

### P0

1. 节目生命周期：候选 → 已采集 → 归档/忽略（本轮已完成忽略/恢复）
2. 转写入库去重：已有转写稿的单集不再重复入队（本轮已完成）
3. 分页/加载更多：节目、单集、任务、转写稿
4. Worker 在线状态与最后心跳

### P1

5. 队列预计完成时间
6. 单集「只看未转写」和排序
7. 调度编辑与未来触发预览
8. 采集任务分页和失败重跑

### P2

9. 任务中心与采集/转写页职责收敛
10. 转写质量反馈与全文检索
11. RSS 健康检查
12. HTTPS/TLS

## 验收建议

- 100+ 节目下，节目库首屏仍然清晰，候选不会被误认为已采集
- 90+ 队列下，能快速找到某一集并调整顺序
- 任意一集转写完成后，能在 5 秒内从页面看到状态变化
- 采集任务能直接回答“哪个节目、哪段时间、新增多少、失败多少”
- 任何弹窗按钮点击都有明确反馈，不出现无响应
